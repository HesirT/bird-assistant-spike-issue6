# 羽迹：观鸟助手项目愿景与功能蓝图

> 让每一次走进自然，都有值得发现、能够理解、可以留下的观察。

**项目名称：** 羽迹（暂定）  
**项目定位：** 面向城市观鸟爱好者的智能探索、辨识、记录与成长助手  
**文档版本：** v0.1 · 2026-10-15  
**文档用途：** 项目立项讨论、需求调研与功能范围确定  
**当前状态：** 产品愿景草案。文中的功能为拟建设能力，用户需求与效果有待实地验证。

## 1. 项目愿景

羽迹希望让普通人更容易开始观鸟，也让持续观鸟的人更方便地积累自己的自然观察成果。

对于初学者，走进一座公园并不意味着能够发现和认识其中的鸟：他们可能不知道去哪里、什么时候去，也不知道该观察哪些特征；即使拍下照片、得到一个鸟名，也未必理解辨识依据。对于已有经验的爱好者，一次活动结束后，大量照片、录音、观察笔记和位置记录又常常分散在不同工具里，整理、核对、检索和分享都需要额外投入。社团领队还需要处理行前准备、成员协作、记录汇总和知识讲解。

羽迹拟将这些环节连接起来：出发前，根据地点、季节、可用时间和个人兴趣帮助用户准备一次观鸟活动；现场通过照片、声音和观察描述提供有依据的辨识辅助，并以低干扰的方式保存记录；活动结束后，帮助用户整理素材、核对物种、生成手记，把每次经历积累为个人图鉴和长期学习资料。在此基础上，逐步支持社团协同观察、区域季节档案和自然教育活动。

项目希望创造的价值是：让用户少一些盲目出行和重复整理，多一些独立辨识的能力、完整可信的记录，以及持续走进自然的兴趣。产品的长期价值，来自用户能够不断回看、修正、学习和使用的真实观察经历。

## 2. 要解决的实际问题

以下问题是需求调研的重点假设，需要通过真实访谈和试用确认其频率与重要程度。

| 环节 | 用户可能遇到的问题 | 希望实现的改变 |
| --- | --- | --- |
| 决定出门 | 不知道哪些地点适合自己的时间、交通条件和经验 | 获得有依据、能执行的活动方案 |
| 行前准备 | 资料过多，不知道这次应该先认识哪些鸟 | 得到与目的地和季节相关的少量重点材料 |
| 现场辨识 | 照片模糊、相似种难分，识别结果难以核实 | 看见候选、依据与不确定点，知道下一步观察什么 |
| 现场记录 | 忙着用望远镜和相机，记录容易遗漏 | 通过简短输入保存信息，允许稍后补全 |
| 行后整理 | 照片、录音和笔记难以对应，连拍素材太多 | 将素材整理为可编辑、可追溯的观察档案 |
| 长期学习 | 看过、拍过，却仍然不能独立辨认 | 从自己的真实经历出发进行对比和复习 |
| 多人活动 | 共同记录混乱，个人所见与团队所见混在一起 | 保持协作效率，同时保留每个人的观察事实 |
| 分享与再利用 | 分享作品和导出记录麻烦，敏感位置容易泄露 | 在保护隐私和鸟类的前提下分享、导出和交流 |

## 3. 目标用户与服务重点

| 用户群体 | 典型需求 | 产品提供的主要价值 |
| --- | --- | --- |
| 入门观鸟者、大学生、城市自然爱好者 | 想接近自然，但缺少知识和活动经验 | 降低第一次出行、观察和辨识的门槛 |
| 经常观鸟与拍鸟的爱好者 | 整理照片、管理记录、寻找后续探索目标 | 减少重复劳动，建立可长期使用的个人档案 |
| 观鸟社团领队、自然教育组织者 | 准备活动、指导新人、汇总和审核记录 | 提供多人协作和教学支持 |

首批试点优先服务同一城市或校园周边的入门与进阶观鸟者，并邀请有经验的鸟友参与资料核对。社团协作在存在真实合作组织后扩展；公众生态监测属于长期方向。

## 4. 完整的用户体验

产品以“一次观鸟活动”为组织单位，将行程、素材、观察结果和后续学习联系起来。

| 阶段 | 用户操作 | 助手提供的支持 | 留下的成果 |
| --- | --- | --- | --- |
| 行前探索 | 选择时间、交通方式、兴趣和目的地 | 地点比较、路线建议、季节信息、准备清单 | 一份可编辑的活动计划 |
| 行前学习 | 查看相关鸟种和辨识要点 | 候选鸟种卡片、相似种对比、观察提示 | 本次观察目标与学习材料 |
| 现场观察 | 拍照、录音、记录数量与行为 | 辅助辨识、快速记录、离线保存 | 带原始证据的观察记录 |
| 行后整理 | 导入相机照片、核对待定记录 | 素材分组、候选复核、信息补全 | 个人确认的活动鸟单与相册 |
| 分享与成长 | 导出手记、回看记录、准备下一次活动 | 图文报告、个人图鉴、针对性学习建议 | 可持续积累的自然观察档案 |

例如，一名学生希望利用周末上午进行首次观鸟。他在羽迹中选择一条适合时间和步行条件的公开路线，提前熟悉几种候选鸟。现场遇到无法确定的鸟时，保存照片和简短描述；没有网络也可以继续记录。回家后，他导入照片，核对候选物种，把仍不确定的记录保留为待鉴定，最后生成一篇仅包含真实确认内容的观鸟手记。下一次出发时，系统可以依据这些经历提供更有针对性的准备材料。

## 5. 功能蓝图

### 5.1 观鸟地图与地点探索

**目标：** 帮助用户选择适合自己的观察地点，并理解推荐依据。

- 以地图和列表展示公开可访问的观鸟地点，支持按距离、交通方式、步行量和可用时间筛选。
- 为地点建立资料卡：环境类型、公开路线、通行条件、设施、信息来源和最近核实时间。
- 展示有来源的历史鸟种记录，区分长期资料、近期报告和未经核实的用户补充。
- 提供季节日历，允许按月份浏览历史记录，同时显示样本量和覆盖时间。
- 结合个人鸟单与兴趣，提示值得进一步认识的鸟种和环境类型。
- 支持用户报告施工、路线关闭等变化，显示报告时间和核实状态。

**实际价值：** 用户能比较地点是否适合自己，而不仅是找到地图上的一个坐标。历史记录作为参考，不表述为本次必然目击或未经验证的精确概率。

### 5.2 个性化行前规划

**目标：** 将“想去观鸟”转化为能够执行的活动安排。

- 用户填写出发位置、可用时间、交通方式、步行能力和希望关注的主题。
- 根据地点资料组织路线、停留点、休息和返程安排，保留时间余量。
- 提供“轻松入门”“摄影观察”“认识某类生境”等活动偏好。
- 汇总需要准备的物品、设备、充电与存储检查，以及必要的通行信息。
- 为本次活动生成简短的鸟种预习卡和观察要点。
- 允许用户修改路线；在天气或开放条件变化时提出备选方案，说明使用的信息及更新时间。
- 支持提前保存活动资料。离线地图仅在所选地图服务允许且实现可行时提供。

**实际价值：** 减少到场后才发现时间不够、路线不合适或准备不足的情况。推荐沿公开许可路线进行，不引导接近巢址或进入限制区域。

### 5.3 多模态辅助辨识

**目标：** 帮助用户逐步缩小候选范围，并保留判断依据。

- **照片辨识：** 上传照片、选择鸟体区域，给出候选物种及参考材料。
- **鸟声辨识：** 上传或录制音频，定位疑似鸟鸣片段，提供候选并支持回听。
- **描述检索：** 根据用户记得的大小、颜色、姿态、行为和环境检索相关鸟种。
- **候选对比：** 比较相似种的关键区别，区分参考资料中的典型特征与当前素材中真正可见的证据。
- **补充观察引导：** 提示缺少哪些有辨识价值的信息，例如其他角度照片或更清晰的原始录音。
- **上下文辅助：** 将地点和季节作为辅助信息，同时允许保留异常但可能真实的记录。
- **不确定结果：** 允许保存为待鉴定，或者仅确认到较粗的分类层级。

**实际价值：** 用户既获得识别建议，也能理解哪些判断可靠、哪些仍需核实。未经校准的模型分数不直接解释为识别正确的概率；照片与录音仅在用户确认关联后共同用于判断。

### 5.4 野外快速记录与离线工作

**目标：** 让记录服务观察，尽量减少现场操作负担。

- 开始、暂停和结束一次活动，记录时间、观察地点、方式和时长。
- 用简短文字或语音记录数量、行为、生境和备注；语音转写结果可稍后修正。
- 将照片、录音和笔记关联到具体观察事件，并区分拍摄时间与上传时间。
- 数量不清楚时允许标为未知，不要求用户为提交记录编造数值。
- 区分目视、听到和其他证据来源；原始录音中的模型候选不自动成为个人确认记录。
- 无网络时保存记录和附件引用，恢复网络后继续上传；展示待同步、失败和已同步状态。
- 支持活动结束后补全信息，处理重复上传和编辑冲突。

**实际价值：** 用户能够专注观察，同时避免活动结束后忘记“何时、何地、看到了什么”。第一版离线能力优先保证记录保存，不默认所有模型推理都能在手机端运行。

### 5.5 鸟片整理与摄影工作台

**目标：** 降低一次活动之后整理大量照片的成本。

- 批量导入照片，读取可用的拍摄时间与设备参数，支持手动修正相机时间偏差。
- 根据时间和图像相似度提出连拍分组建议，允许人工拆分与合并。
- 辅助筛选明显模糊、遮挡严重或主体过小的照片，推荐代表图片。
- 对分组提出鸟种分类建议，经用户确认后加入对应档案。
- 建立未知鸟种、待复核和精选照片等视图。
- 根据可见问题和已有参数提供摄影改进提示，区分观赏效果与辨识证据质量。
- 保留原片和处理版本；裁剪、压缩及其他处理不覆盖原始证据，不自动删除照片。

**实际价值：** 将相机中的大量素材整理为可浏览、可检索、能支持观察记录的相册。同一连拍组不自动判定为同一个体；生成式补全的细节不得用于物种鉴定。

### 5.6 个人图鉴、愿望清单与学习成长

**目标：** 将每次观察转化为长期积累的知识和兴趣。

- 用个人照片、录音和笔记建立图鉴，记录初次观察及后续重访经历。
- 将“想认识”“目视确认”“听声确认”“拍摄留证”“仍需复核”等作为可组合的状态，保留各自依据。
- 支持查看同一鸟种在不同日期、环境和观察活动中的个人记录。
- 提供有来源的相似种、不同年龄或季节外观对比；无法核实的内容不自动生成事实结论。
- 根据待定记录和用户自评，推荐少量辨识练习与回顾材料。
- 将愿望清单与下一次活动计划关联，帮助用户准备后续探索。
- 以持续观察、记录完整性和学习进步设计成就，避免以追逐稀有鸟或接近距离作为奖励目标。

**实际价值：** 用户能看到自己逐渐会辨认、会记录的变化，并用过往经历指导下一次活动。

### 5.7 观鸟手记、年鉴与私人记忆搜索

**目标：** 让记录容易找回，也容易表达和分享。

- 根据已保存的事实生成可编辑活动手记，整合路线、照片、鸟单和用户备注。
- 生成月度回顾或年度观鸟相册，展示个人足迹、初见记录和精选作品。
- 支持按鸟种、活动、地点、时间、记录状态和标签搜索。
- 提供自然语言检索，例如“找上次社团活动中仍没认出的鸟”，返回匹配依据。
- 导出 Markdown 手记、CSV 鸟单及图片；PDF 和更多版式可作为后续扩展。
- 分享前预览公开内容，选择是否展示地点、轨迹、同行者及照片定位信息。

**实际价值：** 用户拥有可带走、可继续整理的个人资料。自动写作仅组织已有内容，不虚构目击、数量、行为或同行者经历；未确认记录在报告中单独标明。

### 5.8 疑难鉴定与社团协作

**目标：** 支持有证据的交流与多人活动，保留各自的观察事实。

- 建立待鉴定案例，汇集原始素材、候选、补充信息和讨论。
- 支持在照片中标注辨识位置，附上解释和资料来源。
- 保留结论更正历史及修改理由，修正后同步更新受影响的个人统计。
- 支持活动发布、报名、名额、取消、行前材料和分组安排。
- 提供组织者、参与者和经邀请审核者的不同权限。
- 将团队汇总鸟单与个人鸟单分开；成员选择自己实际确认过的记录。
- 对多人记录同一观察事件提出合并建议，经确认后处理，不直接累加数量。

**实际价值：** 社团可以减少散落在群聊和个人相册中的信息，新手也能通过讨论了解判断过程。审核者的身份与能力需要真实确认，不能把点赞数或重复采纳同一AI建议当作可靠鉴定。

### 5.9 声景观察与区域季节档案

**目标：** 在记录足够可靠、存在持续参与者的条件下，支持更长期的自然观察。

- 上传环境录音，展示声谱图、疑似鸣叫时间段和候选物种。
- 允许回听、人工确认、否定和标记不确定片段。
- 为固定地点建立多次观察档案，比较不同日期的记录。
- 汇总区域季节记录，展示样本量、观察时长、设备和方法等背景信息。
- 为校园自然教育或社团调查生成描述性报告，逐步探索授权后的数据合作。

**实际价值：** 帮助用户理解一个地方随季节变化的观察记录，而非只追求一次打卡。

**适用边界：** 鸣叫检测次数不等于鸟只数量，未检出不等于不存在。只有在采样方法和观察投入可比较时，才讨论相应差异；课程原型不直接承诺种群数量估计、迁徙预测或生态健康诊断。

### 5.10 贯穿全流程的智能助手

**目标：** 降低操作和资料查找成本，让用户通过自然语言使用已有功能。

示例请求包括：

- “周末只有两小时，帮我比较两个适合入门的地点。”
- “这两个候选主要差在哪里？我的照片能看清那些位置吗？”
- “把今天还没确认的记录找出来。”
- “用这些已经确认的记录整理一篇观鸟手记。”
- “找出我去年秋天在这个公园拍过的照片。”

助手根据实际记录、资料来源和系统能力返回结构化结果。涉及公开分享、批量修改、合并或删除记录时，先展示影响范围，再由用户确认。事实查询给出来源；服务不可用时，已有记录、检索和手动编辑仍可使用。

**实际价值：** 用户能够更方便地完成具体任务，而不需要反复在多个页面复制信息。

## 6. 产品特色与价值主张

### 6.1 以真实观鸟经历连接功能

地点推荐产生行前材料，现场观察留下证据，素材整理形成个人图鉴，待定记录又成为学习和下一次观察的起点。各模块围绕同一份活动与记录工作，减少反复录入。

### 6.2 让辨识过程可理解、可修正

用户能够区分模型建议、个人确认和协作复核，查看依据与更正历史。暂时不能识别也可以形成有价值的记录，之后继续补充。

### 6.3 同时服务户外体验与行后整理

户外强调快速操作、少打扰和可靠保存；行后强调批量处理、核对、搜索与分享。手机和电脑承担不同任务，围绕同一活动保持一致。

### 6.4 让学习贴近用户自己的经历

学习内容由真实观察和疑问触发。个人图鉴既是回忆，也是可反复使用的辨识资料。

### 6.5 将保护自然融入默认行为

敏感位置保护、低干扰导览和记录质量要求直接体现在产品流程中，使探索兴趣与负责任的观察能够同时成立。

现有 Merlin 已覆盖照片与声音辨识、个人鸟单以及按地点和季节探索鸟种等能力。[1] 因此，本项目不将这些单项功能宣称为独创。拟验证的差异点是：本地活动适配、证据化辨识、照片整理与观察档案的紧密关联，以及面向真实社团的协作体验。

## 7. 核心版本与长期扩展

完整愿景保留丰富功能，课程版本优先保证用户能够独立完成一次真实活动。下表是范围建议，需要在团队能力、数据与模型试验后确认。

| 优先级 | 拟交付能力 | 完成标志 |
| --- | --- | --- |
| P0：核心版本 | 用户与私人档案、活动创建、有限地点资料和简单行前计划 | 用户能选择地点并建立可编辑活动 |
| P0：核心版本 | 照片辅助识别、候选对比、手动确认与待定状态 | 识别建议能与原始照片和记录对应 |
| P0：核心版本 | 快速记录、离线暂存、附件关联与同步状态 | 现场网络中断不导致已保存记录丢失 |
| P0：核心版本 | 批量照片导入、基础时间分组、人工纠正 | 可以完成一次活动的素材整理 |
| P0：核心版本 | 个人鸟单、基础图鉴、检索、Markdown/CSV 导出 | 用户能回看、修改并带走自己的成果 |
| P0：基础质量 | 权限、敏感位置处理、异常提示、部署和必要测试 | 系统可独立体验，关键流程可复现 |
| P1：重点增强 | 鸟声辅助识别、相似度分组与代表照片推荐、个性化目标、学习卡片 | 依据用户反馈选择其中一至两项做深 |
| P1：协作增强 | 小规模活动组织、疑难鉴定和团队记录汇总 | 有真实合作社团时优先建设 |
| P2：长期扩展 | 自动重规划、区域季节日历、固定点声景、年鉴与深入摄影辅助 | 在数据积累和持续需求得到验证后扩展 |

**建议试点范围：** 选择一个城市或校园周边，先核实三至五个公开观鸟地点，围绕约三十至五十种当地常见鸟准备资料与评测样本。这个范围用于验证流程和知识覆盖，不等于承诺对所有鸟种都具备可靠识别能力；范围外仍允许保存记录和待定结果。

**第一版不承担的目标：** 从零训练覆盖全球的识别模型、实时精准追踪鸟的位置、自动确认所有鸟种、自动推断个体数量，以及未经验证的生态或迁徙预测。

## 8. 数据与智能能力的实现原则

### 8.1 先核实资料，再扩大推荐范围

- 基础鸟类资料、参考照片和声音需要记录出处与使用许可。
- 优先争取合作鸟友和社团授权，配合团队实地记录建立试点资料。
- 第三方观测数据的地区覆盖、更新频率和访问条件需要在开发前验证。
- eBird 提供不同形式的数据访问；其 API 主要提供有限的近期及汇总数据，不能据此假设已获得完整历史数据或媒体使用权。[2]
- 统一鸟种标识与分类版本，保存常用名称映射，避免仅按中文名称合并记录。
- 公开可查看不等于允许批量抓取、再分发或用于训练；演示数据与真实记录明确区分。

### 8.2 分工明确的智能能力

物种识别模型提供候选，已核实的知识资料提供辨识依据，大语言模型帮助组织解释、检索和整理内容，业务规则负责状态与权限。用户确认的事实与机器推测分别保存。

BirdNET 可作为声音辨识的候选方案；实际选型应验证所需鸟种的效果、部署成本与具体模型许可，不将开源代码许可等同于所有权重和素材的许可。[3] 图像模型也需要通过当地真实照片评测，再确定核心版本承诺。

### 8.3 结果有出处，失败可恢复

- 重要地点信息、辨识知识和外部记录显示来源与时间。
- 模型低分、素材质量不足或证据冲突时允许不确定结果。
- 模型和外部接口超时不影响手动记录，失败任务可重试。
- 同步、批量导入和编辑操作可查询状态，避免静默丢失或重复记数。
- 数据可导出，用户可控制公开范围并删除自己的资料。

## 9. 观鸟伦理、隐私与记录可信度

这些要求直接影响地图、分享和识别设计，应与功能同时实现。

1. **保护敏感位置。** 对敏感物种、巢址等信息隐藏或降低位置精度；分享时同时检查文本、轨迹及图片定位元数据。eBird 也对敏感物种采取限制公开措施。[2]
2. **减少现场干扰。** 路线遵守场地规则，不提供诱鸟播放功能，不鼓励接近巢区或为了拍摄改变鸟的行为。观鸟伦理规范强调鸟类福祉与对敏感场所的谨慎。[4]
3. **区分不同证据。** 模型候选、用户确认和协作审核分别标记；团队记录不自动进入每个人的已见清单。
4. **保留原始素材。** 原始照片和音频与编辑版本分开；生成式修复不成为鉴定证据。
5. **审慎解释统计。** 展示观察时长、范围和样本量；记录频次、鸣叫事件与个体数量分别处理。
6. **尊重参与者隐私。** 精确轨迹、同行者信息及录音中的个人谈话默认不公开；涉及协作和分享时明确可见范围。

## 10. 如何验证“真的有用”

项目效果通过真实任务验证，不以页面数量、模型数量或生成文本长度作为主要成果。以下是拟采用的评估方式，不代表已经取得的结果。

| 验证目标 | 评估方法 | 观察指标 |
| --- | --- | --- |
| 新手能独立完成活动流程 | 邀请初学者从选择地点到保存并导出一条真实记录 | 任务完成率、求助次数、耗时、误操作 |
| 行后整理更省事 | 使用相同素材，比较原有整理方式与本产品 | 整理耗时、遗漏数量、错误关联、人工修正量 |
| 辨识建议值得参考 | 使用独立确认的当地样本，包含清晰、模糊、无鸟及范围外素材 | 候选覆盖、误识、拒绝判断表现，以及分场景错误分析 |
| 解释帮助用户学会观察 | 让用户在未见过的相似样本上说明辨识依据 | 能否指出关键证据，而非只记住鸟名 |
| 野外使用可靠 | 模拟断网、重启、重复上传和同步冲突 | 是否丢记录、是否重复生成、是否能恢复 |
| 用户愿意继续使用 | 让小规模用户试用两次活动，访谈第二次使用体验 | 实际复用功能、未使用原因、最愿意保留的能力 |

评测样本应与开发调试素材分开，避免把同一连拍组或同一段录音的近似片段分到两边。报告样本量、覆盖范围和失败案例，不用少量精选演示宣称整体准确率。

## 11. 开发与验证路线

| 阶段 | 重点工作 | 交付与判断依据 |
| --- | --- | --- |
| 需求与可行性验证 | 访谈新手、拍鸟用户和领队；核实地点资料；测试候选识别方案 | 确认最重要的两三个问题、可用数据和识别边界 |
| 首个可用版本 | 完成活动、记录、照片、手动鉴定、基础图鉴和导出 | 即使暂不依赖AI，仍能记录并整理一次活动 |
| 核心智能体验 | 接入照片辨识、候选对比、基础整理和简单行前计划 | 用户能完成核心流程，系统保留依据与不确定状态 |
| 实地试用与打磨 | 实测断网与户外交互；根据反馈精选一至两项增强功能 | 用真实任务展示价值变化，补齐失败处理与数据保护 |
| 交付与展示 | 部署、使用说明、测试结果、数据与素材来源说明 | 提供可独立体验的系统和可复现的演示样例 |

## 12. 项目展示的核心故事

答辩围绕一次完整活动展开，使用获得许可的真实素材；若使用模拟数据，应清楚标注。

1. 用户选择可用时间与地点，系统展示活动方案和推荐依据。
2. 用户上传一张有辨识难点的照片，系统展示候选与证据缺口；用户保留待定状态。
3. 现场录入另一条观察，切换为无网络状态后仍能保存，恢复网络后完成同步。
4. 导入一组连拍照片，系统提出分组建议，用户修正关联并确认记录。
5. 已确认记录进入个人图鉴，待定记录进入复查箱，活动手记可以预览并导出。
6. 回看这次活动，用户能找到原始证据、修改结论，并获得下一次观察的学习提示。

这条演示主线呈现的成果是：从一次出行和一批零散素材，形成一份用户理解、愿意保存、能够继续使用的自然观察档案。

## 13. 立项后优先确认的问题

- 用户最愿意持续使用的是行前规划、辨识解释，还是鸟片整理？需要通过访谈和试用排序。
- 团队能否获得本地有经验鸟友的帮助，用于核对资料和评测样本？
- 所选地区的记录、图片和录音能否合法、稳定地获取并使用？
- 核心设备是手机浏览器、独立移动应用，还是手机记录与电脑整理结合？先验证必要的离线和上传能力。
- 合作社团是否确实愿意参与试用？若没有合作方，协作模块不作为首版依赖。
