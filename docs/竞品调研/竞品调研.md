# 观鸟助手竞品调研

2026-10-23 · Issue 4 · v0.2

## 结论与范围

已有产品分别覆盖识别、私人清单、地图鸟讯、社区鉴定和拍后选片。我们建议先验证一条完整的小程序流程：探索地点，保留本人观察素材，复核候选，再分别选择收藏与公开用途。单个常见功能及中文、微信入口，都不足以说明产品具有独特优势。

本调研对应 Issue 4 的九个维度，保留国内对照并增加成长参考，共比较8个产品，覆盖题目建议的5类对象。目标是帮助收敛需求与原型，不在本阶段承诺批量选片或游戏首发。

资料核验日期为2026年10月23日。功能以官网、官方帮助和开发者商店说明为依据；“我们的判断”、可借鉴点与差异机会属于设计分析。流程数字表示归纳后的任务阶段，首次配置另算；本次未安装并实测竞品，不能用阶段数做点击数、速度或易用性排名。

## Merlin Bird ID

**目标用户**  希望认识眼前或耳边鸟类的新手及观鸟者。[M1]

**核心场景**  观鸟中识别，观鸟前后查看鸟种资料。[M1]

**三个核心功能**  照片识别；声音识别；鸟种资料与个人清单。[M1, M3]

**使用流程**  照片路线归纳为4阶段：提供照片及背景信息 → 比较候选 → 选择鸟种 → 确认日期地点并保存。属于文档归纳，不是点击次数实测。[M1, M3]

**数据来源**  识别模型与鸟种资料，eBird 记录为地区候选提供依据。[M1, M2]

**优点**  我们的判断：多个识别入口与资料对照衔接清楚，适合学习；官网说明照片和声音识别可离线使用。[M1]

**限制与待验证项**  声音覆盖有地区限制，不能把全球鸟种资料覆盖理解为全球声音识别覆盖。保存观察需要网络；私人保存已经存在。[M2, M3]

**可借鉴点**  候选对照、资料入口和选择后的确认步骤。我们的实现应允许待鉴定保存，不强迫用户选一个鸟名。

**差异机会**  可测试待鉴定记录与分用途发布的连贯性。照片识别、声音识别、私人清单本身都不是我们的独有功能。


## 懂鸟 AboutBirds

**目标用户**  需要中文鸟名、识别和个人鸟类资料的观鸟者，为我们根据产品描述推断的受众。[D1]

**核心场景**  野外识别与事后整理个人资料。[D1]

**三个核心功能**  离线图片及声音识别；鸟类资料；私人媒体库与成就清单。[D1]

**使用流程**  仅作3阶段任务示意：提供素材 → 查看识别及资料 → 整理个人媒体。公开介绍不足以确定实际界面顺序，需另测小程序。

**数据来源**  产品介绍列出识别能力、鸟类资料，以及从 eBird、记录中心等导入个人清单的能力；本次不核定其训练数据。[D1]

**优点**  我们的判断：它是更直接的国内对照，已有识别、中文资料与私人积累，调研应同时纳入国内产品。

**限制与待验证项**  iPhone 描述称其为懂鸟小程序的离线版本；App 与小程序功能一致性及本地识别表现需实测。[D1]

**可借鉴点**  鸟名表达一致、识别旁边可查资料，以及私人素材便于回看。

**差异机会**  测试校园日常观察、相似种复核和分享控制是否足够顺畅。中文、微信入口或多模态识别不能单独作为独有卖点。


## BirdNET App

**目标用户**  想知道鸟鸣来自哪种鸟的用户，以及愿意提交录音的观察者。[B1]

**核心场景**  观鸟中录音并检查建议鸟种。[B1]

**三个核心功能**  声音采集；候选及分数；可选提交观察。[B1]

**使用流程**  官方列出4阶段：录音 → 分析 → 候选建议 → 可选贡献。这是任务阶段，不等于4次点击。[B1]

**数据来源**  用户录音与 BirdNET 神经网络；网站说明位置是可选信息。[B1]

**优点**  我们的判断：单一声音任务容易聚焦，适合作为录制、回听和候选呈现的对照。

**限制与待验证项**  项目页与商店介绍的覆盖口径不同，不能混用为某个已安装版本的能力。App、Live、Analyzer 分开看；噪声及本地鸟种表现未实测。[B1, B2]

**可借鉴点**  录制状态、回听、分析中的反馈，以及结果可以复查。分数应带模型来源与含义，不能直接写成正确概率。

**差异机会**  把录音及原始候选长期关联到自己的观察，允许后来更正鸟名；识别失败也能保留素材。


## eBird

**目标用户**  记录所见所闻、查找观鸟地点并贡献观测数据的鸟友。[E1, E2]

**核心场景**  观鸟前找地点，观鸟中记清单，结束后提交与回看。[E1, E2]

**三个核心功能**  观察清单；区域和热点探索；个人观察统计。[E1, E2]

**使用流程**  已配置后的清单任务归纳为4阶段：开始观察并记鸟种数量 → 确认地点 → 结束并检查过程信息 → 提交。首次账号及鸟包配置另算。[E1]

**数据来源**  鸟友清单；探索工具同时关联 Macaulay Library 媒体与 Merlin 资料。[E1, E2]

**优点**  我们的判断：把鸟种与观察地点、时间和观察过程放在一起，比只有鸟名更适合回顾一次活动。

**限制与待验证项**  完整清单和过程信息可能需要新手解释，这是待测假设。官方说明未提交清单可留在手机，但不等于已同步到账号。[E1]

**可借鉴点**  观察时间与上传时间分开、历史鸟讯标日期、清楚区分手机草稿与已同步记录。

**差异机会**  以轻量私人观察为入口，再选择补全资料和发布。热点地图和鸟种统计已有成熟先例，不宜当作独有能力。


## iNaturalist

**目标用户**  记录自然、向他人求助或协助鉴定的人，范围不限于鸟类。[I1, I2]

**核心场景**  记录一次遇见，之后查看建议、讨论和鉴定变化。[I1]

**三个核心功能**  带素材的观察；AI 候选对照；社区鉴定和讨论。[I1, I2]

**使用流程**  新 iPhone AI 相机路线归纳为5阶段：拍摄 → 检查匹配 → 保存到本机 → 可选编辑上传 → 查看后续鉴定。文档明确保存与上传不同。[I1]

**数据来源**  用户观察和鉴定形成社区资料，识别模型也使用社区确认的观察。[I2, I4]

**优点**  我们的判断：候选与社区鉴定可持续复核。质量状态有规则，不能把选中 AI 候选直接算作专家确认。[I3]

**限制与待验证项**  已上传的观察为公开记录，隐藏位置不等于隐藏整个观察；新 App 可保留尚未上传的本机记录。不要据旧描述断言它完全不能私人保存。[I1, I5]

**可借鉴点**  原始素材、AI 候选、用户选择与社区意见分开；清楚说明整条记录的可见性和地点可见性。

**差异机会**  测试私人收藏、地图贡献和论坛帖子的独立控制是否易理解。私人保存与相似种对照都不能直接宣称为首创。


## 中国观鸟记录中心

**目标用户**  在中国提交、查询观察记录的鸟友。[C1, C2]

**核心场景**  观鸟前查记录，观鸟中后整理并提交本人观察。[C1, C2]

**三个核心功能**  观察记录提交；地区及鸟种查询；观察统计。[C1]

**使用流程**  依据提交规则归纳4阶段：确定日期地点 → 填写本人鸟种与数量 → 添加或后补证据 → 检查提交。这是任务分析，小程序屏幕与点击次数待实测。[C2]

**数据来源**  用户本人实际所见或所闻的记录及对应时间地点的素材。[C2]

**优点**  我们的判断：国内记录规则直接相关，官网也提供微信小程序入口或说明。[C1]

**限制与待验证项**  网站规则不等于小程序的逐屏功能清单。小程序导航、权限、失败恢复及私人整理能力需要现场走查。

**可借鉴点**  本人观察与他人素材分开、允许后补证据、解释观察地点及日期、重视常见鸟记录。[C2]

**差异机会**  验证新手的快速待鉴定记录，再补全和分享是否更顺畅。国内记录平台及微信入口已经存在。


## 慧眼选鸟 SuperPicky

**目标用户**  拍摄后需筛选大量照片的鸟类摄影者，是 Issue 4 明确点名的产品。[S1, S2]

**核心场景**  观鸟后对照片进行初筛、对比和整理。[S2]

**三个核心功能**  鸟类照片质量建议；连拍分组；筛选、对比和人工改星。[S1, S3]

**使用流程**  4阶段归纳：选照片目录 → 设置并运行分析 → 查看分组和评分 → 复核并整理结果。未安装计时或测量点击数。[S2, S3]

**数据来源**  用户照片、图像模型与相机信息；罕见度另来自 GBIF 记录衍生指标，与保护等级不同。[S1, S2, S4]

**优点**  我们的判断：围绕头部清晰度和连拍复核，解决拍后选片的具体问题；自动建议保留人工选择空间。[S2, S3]

**限制与待验证项**  官网为桌面产品；本次流程依据 4.5.0 教程，首页显示更新版本。文件夹、RAW 和元数据操作不能直接照搬到微信小程序。[S1, S2]

**可借鉴点**  后续可做同次观察多图对比和代表图选择，显示建议原因并允许改选。首版避免自动移动或删除用户原片。

**差异机会**  把少量素材与观察关联；批量选片保留 PHOTO-01 候选。资料中的罕见度指标不能直接当作成长奖励依据。


## Seek by iNaturalist

**目标用户**  刚开始探索自然的人与家庭。[K1, K2]

**核心场景**  边探索边认识生物，之后回看收集与挑战进度。[K1, K2]

**三个核心功能**  相机即时识别；本机观察积累；徽章与挑战。[K1, K2]

**使用流程**  4阶段任务归纳：打开相机 → 查看识别 → 加入观察 → 查看成长反馈。此为文档归纳，具体徽章触发与点击数待实测。[K1, K2]

**数据来源**  模型基于 iNaturalist 及合作站点的社区资料；通常使用的本机模型可能比在线模型旧。[K1, K2]

**优点**  我们的判断：成长反馈可以服务自然学习，不必依赖公开发帖；官方说明普通使用无需账号。[K2]

**限制与待验证项**  本机 AI 结果不等于社区复核。普通本机使用与可选登录发布到 iNaturalist 要分开说明。[K2]

**可借鉴点**  成长反馈可独立于社交分享。我们的后续规则应允许常见鸟和待鉴定观察产生学习价值。

**差异机会**  测试记录笔记、补充线索和学习相似种后获得庭院装饰。保留 BADGE-01 候选，不把追稀有鸟或公开精确地点设为奖励条件。

## 对本项目的设计建议

### R1 保留候选比较和待鉴定保存

ID-04 / P12 / P32  用户应能看参考说明、保留原始建议，再选择或更正鸟名。模型分数与用户选择各自保存；跨来源不直接平均分数。

### R2 地图优先展示可解释的历史观察

MAP-01 / MAP-02  显示观察日期与地点信息，保持地图、详情和返回后的视口一致。真实地图服务接入仍需 Issue 5；历史记录不能包装成鸟仍在现场。

### R3 验证私人保存与公开用途的独立控制

G02 / G03 / G07  私人观察、收藏、地图贡献和论坛帖子各自显示状态。公开前预览包含哪些字段；隐藏位置和隐藏整条记录分别解释。

### R4 参考检索、复核和模型训练分开决策

REF-01 / DATA-01 / G10  外部资料可查不代表素材可复用。保留来源、授权和复核状态；用户选中的标签不能直接升级为已复核样本。真实接入另行验收。

### R5 批量选片保持候选范围

PHOTO-01  可先评估同一次观察的少量图片对比、代表图选择。大批 RAW、目录移动和元数据写回需要单独验证，不计入当前原型已实现。

### R6 成长先验证学习反馈，再考虑扩展小游戏

BADGE-01  可提议完成笔记、补充线索、学习相似种后获得羽叶或庭院装饰。奖励与公开分享分开；规则应处理重复提交和撤回。识别正确率或留存提升均尚未验证。

## 后续验证任务

**U1 找一次日常观察**  让目标用户从地图找到一条有日期的记录，打开并返回；检查是否误以为鸟仍在原地。

**U2 不知道鸟名仍可完成**  提供模糊图片或无可靠声音候选，观察用户能否保存待鉴定、补充素材并再次找到它。

**U3 理解两个分数**  展示来自不同来源的建议，询问用户是否将分数理解为正确概率，以及分歧后如何选择。

**U4 私人保存与发布**  先保存私人记录，再仅选择一个渠道发布，询问谁能看到哪些字段；撤回后再次检查。

**U5 成长是否有吸引力**  用小型成长草图比较笔记、学习和收集奖励，记录用户实际选择与原因；不先假定一定提高留存。

**U6 国内直接对照**  由团队在微信中实际走查懂鸟与记录中心的同一任务，记录版本、日期、步骤、权限和失败恢复，补足文档调研。

## 验证范围

尚未实测中国大陆网络可用性、微信内权限、端侧或服务端推理速度、目标鸟种准确率、耗电和存储开销。官网功能描述不能替代这些结果。

部分页面存在版本差异：BirdNET 项目页与商店的覆盖描述不同；慧眼选鸟首页版本新于所引用教程。只引用对应界面的明确行为，不合并覆盖数或跨版本保证。

eBird 部分主站页面出现自动访问限制，本报告采用可读取的官方帮助说明；懂鸟主站未提供可读正文，具体功能以开发者商店描述为依据。未取得的小程序走查结果不补写为事实。
